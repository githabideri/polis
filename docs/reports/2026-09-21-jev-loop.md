# Jev-loop v1 — first measured run (2026-09-21)

**Loop:** polis harness (deterministic sensing) → state text → Laya 421M
choice question via openjev `/v1/systemone` (~900 ms/call, CPU) → confidence
gate → execute via `/polis/command` → measure vs a rule oracle.

**Task:** "mine the rock at (bx+8, by+1, bz), then return to base (bx, by, bz)".
Bot starts at base. Flags `near_target` / `near_base` / `rock_mined` are
computed by the loop (harness data) — Laya does the situation→action mapping,
no arithmetic.

## Result (bot #5, 8 steps)

| step | facts (near_t, near_b, mined) | oracle | Laya | conf |
|---|---|---|---|---|
| 1–8 | (no, yes, no) — unchanged, bot never moved | goto_target | **mine_target** | 0.33 (steps 1–2, gated), 0.59 (steps 3–8, **not** gated) |

- **oracle match: 0/8 (0%)**
- **low-confidence gates (<0.5): 2/8** — caught the first two tries, not the rest
- **exec success: 0/8** — `mine` correctly refused ("Target too far: 8.1 > 4.5");
  step 1 additionally hit "Tool tier insufficient" (pickaxe given but not the
  active tool — execution-side detail, not a Laya issue)
- **avg Laya latency: 917 ms**, 8 steps in ~8 s wall

## The failure mode (the actual finding)

Laya read the goal's verb ("**mine** the rock…") and mapped the whole situation
to `mine_target`, ignoring `near_target=no` — the bot is 8 blocks away and the
correct first action is travel. Classic small-model **goal-word bias**: the
task description's salient noun/verb outcompetes the pre-digested state facts.
Confidence stayed at 0.59 — *above* the 0.5 gate — so the honest-hedging
mechanism did not save us here: the model is confidently wrong about *which*
action, while (correctly) not hedging much.

## What v2 should try (in order of cost)

1. **Phase-split the goal** in the state text: "current phase: travel to
   target (rock not yet mined, bot not at target)" → ask "which action serves
   the *current phase*?" (kills the verb-bias by construction)
2. **Explicit operational rule in `instructions`**: "Choose mine_target only
   if near_target=yes; otherwise choose goto_target while the rock is
   unmined." (tests whether a 421M can follow a stated decision rule —
   unknown, measure)
3. **Noul decomposition**: two yes/no questions ("Is the bot at the target?"
   / "Is the rock already mined?") + a deterministic combinator — noul is the
   most reliable question type; the combinator becomes the oracle we already
   have (degenerate but valid data point)
4. Only if 1–3 fail: this task class doesn't fit a 421M; route to a bigger
   model (llmlab) for planning, keep Laya for the reflex layer.

## v2: phase-split state (run 2026-09-21, same bot/world)

State text now carries a deterministic `current phase` (travel / mine /
return / done — computed from the same facts) plus explicit phase meanings;
the question asks for "the single action that serves the current phase".

| | v1 (goal word) | v2 (phase split) |
|---|---|---|
| oracle match | 0/8 | 0/8 |
| Laya choice | mine_target 8/8 | mine_target 8/8 |
| confidence | 0.33–0.59 (2/8 gated) | **0.17 (8/8 gated)** |
| exec success | 0/8 (refused: too far) | 0/8 (refused: too far) |
| avg latency | 917 ms | 2203 ms (longer state) |

**Reading:** the 421M still cannot do the phase→action mapping (the "mine"
verb in the task name keeps winning the argmax), *but* making the state
internally inconsistent with that guess collapsed its confidence from 0.59
to 0.17 — from confidently-wrong to **honestly-unsure**. That is the
difference between a gate that fails (v1: 6/8 wrong answers sailed through
the 0.5 gate) and a gate that works (v2: 8/8 caught). A
confidence-gated fallback to the deterministic policy would have scored
8/8 on this task in v2.

**Architecture consequence (v3 direction):** stop asking the 421M to *select*
among actions (multi-option choice is where it fails); let the deterministic
policy *propose* and ask Laya a calibrated **noul** ("Is this the right next
action for this situation? yes only if …; no otherwise") — noul is the most
reliable question type on this box. Laya becomes a veto/confirmation layer
that escalates to a bigger model (llmlab) on a confident "no"; the reflex
layer stays at ~1–2 s/call on CPU.
